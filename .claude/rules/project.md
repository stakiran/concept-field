# concept card / concept deck

既存語を組み合わせて新しい概念を立てる遊びを、誰でも参加できる「規格」として
確立するプロジェクト。リポジトリ名は `concept-field`。

## 核となる思想

- **造語は使わない** — 既存語の意外な隣接で、見慣れた言葉がぐらっと再発見される
  快感が商品。新語を発明した人ではなく、既存語の隠れた隣接を発見した人が勝つ。
- **言語のみ、イラストなし** — 概念は言葉のまま差し出すからこそ美しい。
  足し算（リッチ）ではなく引き算（端正）を目指す。
- **場は運営しない** — テンプレート（規格）だけ定め、見せる手段は各自に委ねる。
  中央非依存であること自体が `default remote` の思想と呼応する。
- **お手本を最初に置く** — ルールで縛らず、吉良野すた本人のカードが事実上の標準に
  なることで「こう書くのね」と背中で教える。

## カードの型（Markdown 見出しへ写像）

- **h1（`#`）** = 概念名（和名＋英名併記）例: `# デフォルト・リモート（Default Remote）`
- **h2（`##`）** = What。定義というほど格式張らない、一行のつかみ。
- **h3（`###`）** = 展開。型は固定しない（中身次第で枚数も可変）：
  - シーケンス型：`住み込み → 出社 → リモート`（現在地をずらすパラダイムシフト）
  - 分類型：要素を h3 で複数列挙（各要素にさらに下位概念名を与えてよい）
  - パラフレーズ型：現象の言い換え・記述

様式（見出し構造）は揃えるが、思考の型は縛らない。

## 展示の構造（GitHub Pages・2階建て）

- **一覧ページ = deck** … 全カードを h1〜h3 全文でグリッド表示。
  密度・図鑑的な一望感。余白は詰めぎみ。
- **個別ページ = card** … 一枚を余白たっぷりに。共有の単位（URL が流通する）。
  疎。h1/h2/h3 の落差が独り占めで映える。

## 技術土台

- GitHub repo、**1 card = 1 markdown file**（`docs/` 配下）。
- GitHub Pages（Jekyll）。デフォルトテーマでは「記事の縦列」にしかならないため、
  **自前の最小 CSS** で並べ方（グリッド）とタイポグラフィの落差だけを整える。
- 色・装飾はほぼ使わない。黒い文字と余白で成立させる。
